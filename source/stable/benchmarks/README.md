# 可复现实验预留

已有实验：05 的 run_scheduler_benchmark.py 使用 WorkflowEngine/Runtime 墙钟模拟；10-A 的 scripts/bench_scheduler_10a.py 调用生产调度决策内核进行确定性事件模拟。10-A 全部原始结果位于 results/scheduler-10a，方法与复现见 [10-A 文档](../docs/scheduler-benchmark-10a.md)。以下保留初期规划历史，不是当前能力声明。

下一阶段候选真实场景：针对负责人提供的仓库快照，完成需求拆解、只读缺陷调查、补丁候选生成、沙箱测试和交叉验证报告。必须先确定数据授权、任务集与验收标准；不能用虚构执行结果代替实际运行。

基线接口为 `BaselinePolicy` / `Scheduler`。后续比较：固定顺序、满足能力和容量约束的 FIFO、经批准的动态调度策略；再分别关闭反馈恢复、替换验证策略做消融。所有组使用相同模型版本、输入、工具权限、预算、超时、验收器及并发上限。串行基线仅改变并发方式，不改变质量要求。

每次实验应保存：数据集/任务版本和哈希、代码提交、模型/提示/工具/验证器版本、策略配置、随机种子、依赖锁文件、硬件环境、原始事件、失败轨迹、人工介入记录与实际费用。闭源模型即使相同 seed 也可能不确定，应重复运行并报告分布和限制。

计划指标（尚未采集）：独立验收通过率、完成时延、排队时延、模型 tokens 与费用、重试次数、人工介入率、恢复成功率。不得只比较成功样本；应报告样本量、失败/超时、原始记录和统计口径。验收器与被测 Agent 隔离。
